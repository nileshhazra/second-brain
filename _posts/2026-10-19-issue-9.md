If you’ve ever waited for an insurance policy quote, you know the frustration: applications disappear into an operational black hole. Behind the curtain, legacy underwriting systems are often a tangle of nightly batch jobs, siloed databases, and spreadsheets passing between underwriters and risk analysts. By the time executive leadership sees yesterday's loss-ratio reports, the market has already moved.

When building the **[Underwriting Cloud Data Platform](https://github.com/nileshhazra/underwriting-cloud-data-platform)** ([Live Demo](https://underwriting-cloud-data-platform.vercel.app)), I wanted to rethink this entire lifecycle from first principles: 

> *How do we take high-stakes insurance policy submissions from the client browser, process transactions in single-digit milliseconds, stream raw audit records to a cloud data lake, and deliver zero-copy real-time executive analytics without a single scheduled batch refresh?*

Here is a breakdown of how modern event-driven cloud architecture and the Lakehouse Medallion pattern solve this end-to-end.

---

### The Architecture at a Glance

The platform bridges real-time transactional processing (OLTP) and analytical lakehouse storage (OLAP) into a single cohesive pipeline:
[ Underwriter Portal ] (React 19 + Vite) │ REST (< 50ms) ▼ [ Express API Gateway ] ├──► [ Azure Cosmos DB ] (NoSQL OLTP Storage, partitioned by /policyType) └──► [ Azure Service Bus ] (FIFO Queue: policy-submissions) │ Event Trigger ▼ [ Azure Function ] (Serverless Ingestion via Entra ID) │ ADLS Gen2 REST ▼ [ Microsoft Fabric OneLake ] ├── Bronze: Raw Partitioned JSON (Audit Trail) ├── Silver: PySpark Cleaned & Flattened Delta Parquet └── Gold: Aggregated Risk & Underwriter Metrics │ ▼ [ Power BI Direct Lake ] (Zero-copy in-memory analytics)
